# 가상 대상자 기능 검증

실제 로컬 데이터 저장소에 `가상대상자_김테스트` 1명을 등록했다.
메모에 `DEMO-CONTEXT-20260907` 표식과 가상 자료임을 명시했다.
등록 전 전체 백업은 데이터 폴더의 `before-demo-*.zip`에 보관했다.
기존 대상자의 기록을 테스트 목적으로 수정하거나 삭제하지 않았다.

| 업무현황 | 서류 건수, 최근 등록·수정 서류 목록, 원본 열기 경로 | 통과 |
| 대상자 관리 | 가상 대상자 등록·검색·선택 | 통과 |

| 상담일지 작성 | 실제 Gemma 모델로 생성 후 DB 저장, 상담일지 조회·PDF 출력 | 실행 통과, 생성 내용 정확성은 아래 제한 참고 |

업무 화면 7개와 사례관리 내부 탭을 직접 생성하여 전환했다. 화면 검증은
PyQt offscreen으로 수행했으며 Windows 글꼴을 등록하여 PDF 본문도 추출 확인했다.
실제 프린터 인쇄와 외부 HWP 편집기 실행은 수행하지 않았다.
서류 원본 열기는 애플리케이션의 각 조회 경로까지 확인하고 대화상자의 대기는 대체했다.

검증 종료 시 가상 대상자에는 초기상담 서류 1건, 상담일지 2건, 첨부 2건이 있다.
서류보관함에서 총 5건으로 조회되며 사정 1건, 목표 1건, 모니터링 2건,
서비스 연계 1건도 등록되어 있다. 실제 데이터와 혼동하지 않도록 가상 자료로 유지한다.

## 발견하여 보완한 문제

- Windows의 설치된 llama-cpp-python 0.3.35가 `llama_backend_init`에서 access violation으로 실패했다.
  별도 설치에서 CPU 0.3.2의 모델 로드·추론을 확인한 후 프로젝트 가상환경에 적용했고,
  Windows 의존성을 검증한 버전으로 고정했다. 공식 CPU wheel 설치 안내:
  https://github.com/abetlen/llama-cpp-python#installation
- 빈 서류 항목이 AI 입력을 차지하면서 핵심 상담 내용이 누락됐다.
  빈 항목을 제외하고 짧은 자료를 묶어 처리하도록 변경했다.
- 단계별 작성 서류와 상담일지가 서류보관함 및 서류 집계에서 빠져 있었다.
  원본 저장소는 유지하면서 통합 조회를 연결했고 최근 서류 목록을 업무현황에 추가했다.
  원본 종류와 ID를 함께 보관하므로 같은 ID의 첨부·상담·작성서류가 혼동되지 않는다.
- AI가 생성한 상담일지에 없는 사실이 덧붙을 수 있어 맥락 재입력 시 원본 상담 메모를 우선한다.

## AI 결과의 제한

초기상담에서는 `하루 한 끼, 밑반찬 지원 희망, 지원 여부 확인 필요`가 반영됐다.
후속 자료에서는 `하루 두 끼로 증가, 주 2회 지원, 9월 14일 확인 예정`이 반영됐다.
최종 자동 갱신(리비전 25)에서는 `9월 7일 첫 수령`까지 올바르게 반영됐고
입력 버전과 처리 완료 버전이 일치하는 것을 확인했다.
그러나 생성 상담일지가 제공하지 않은 시각·방법을 작성했고, 한 차례 맥락 요약에서
지원 시작일을 9월 7일 대신 9월 1일로 잘못 작성했다.
따라서 AI 실행과 갱신이 작동한다는 확인은 내용 정확성 보장을 의미하지 않는다.
담당자가 원본과 비교하여 검토해야 하며 가상 AI 상담일지를 실제 기록으로 사용하면 안 된다.

## 재검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe verify_demo.py --phase ui
```

단위·회귀 테스트 26개 통과. `verify_demo.py`는 명시적으로 실행하는 검증 도구다.
`--phase context`는 실제 모델로 가상 대상자의 맥락을 다시 생성하므로 시간이 걸린다.
`--phase initial`, `followup`, `register`는 기존 가상 자료를 찾아 중복 생성을 피한다.
`--phase counsel`은 새 AI 상담일지를 추가하므로 반복 실행 시 이력이 추가된다.
