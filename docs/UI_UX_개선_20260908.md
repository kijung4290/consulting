# 상담 업무 중심 UI·UX 개선

## 업무 메뉴 단순화

좌측 업무 메뉴를 7개에서 네 가지 일로 줄였습니다. 화면을 없앤 것이 아니라, 같은 일에 쓰는
화면을 한 메뉴 안의 탭으로 모아 이동 횟수를 줄였습니다.

| 업무 메뉴 | 안에 있는 탭 | 이전 메뉴 |
| --- | --- | --- |
| 대상자 관리 | 대상자 목록 · 확인할 일정 · 최근 상담 · 최근 서류 | 업무 현황 + 대상자 관리 |
| 사례관리 | AI 대상자 맥락 · 단계별 서류·작성 이력 · 욕구·위기도 사정 · 목표·개입계획 · 모니터링 일정 · 서비스 연계 | 사례관리 |
| 서류작성 및 보관함 | 상담일지 작성 · 서류 보관함 | 상담일지 작성 + 서류 보관함 |
| 데이터 관리 | 서류 양식 · 데이터 백업·복원 | 서류 양식 관리 + 데이터 관리 |

대상자 관리가 시작 화면입니다. 화면 위쪽에 KPI 카드 네 장과 빠른 실행 바를 두고, 그 아래
탭에 목록과 일정·최근 기록을 넣었습니다. KPI 카드를 누르면 해당 목록으로 바로 이동합니다.
대상자 목록 탭의 작업 버튼은 `선택한 대상자:` 라벨 아래에 모아, 위쪽 빠른 실행 바와 역할을
구분했습니다.

메뉴와 화면 인덱스는 `app.py` 상단의 `NAV_MENUS`, `PAGE_*`, `CLIENT_TAB_*`, `DOCS_TAB_*`,
`DATA_TAB_*` 상수로 관리합니다. 화면을 옮길 때는 `switch_page` 대신
`open_client_tab`, `open_counseling_writer`, `open_document_vault`, `open_form_designer`를
사용합니다.

## AI 작업 진행 표시

AI 작업이 돌고 있는지 알 수 없다는 문제를 세 곳에서 함께 보여 주도록 고쳤습니다.

1. **사이드바 `AI 작업 상태`** — 어느 화면에 있어도 보입니다. 1초마다 갱신하며 지금 하는 일과
   경과 시간을 적습니다. 예: `● 김OO 맥락 갱신 중 / AI가 기록 읽는 중 · 자료 2/4 · 7초 경과`.
   진행률을 셀 수 있을 때(맥락 갱신의 자료 묶음)는 진행 막대도 함께 채웁니다.
   할 일이 없으면 `진행 중인 작업 없음`, 모델이 없으면 `AI 모델 없음`과 대기 인원을 알립니다.
2. **사례관리 · AI 대상자 맥락 탭** — `맥락 다시 갱신`을 누르면 곧바로 상태가 바뀝니다.
   진행 중에는 `🔄 이 대상자 갱신 중 · …`과 자료 진행 막대를 보여 주고 버튼을 `갱신 중…`으로
   잠급니다. 멈춰 있을 때는 그 이유를 구분해서 적습니다: 실패(사유 표시), 모델 없음,
   다른 대상자 처리 대기, 곧 시작, 최신 반영 완료.
3. **서류작성 및 보관함 · 상담일지 작성 탭** — 진행 막대 아래에 지금 단계를 적습니다.
   모델을 처음 불러올 때(수십 초 동안 화면 변화가 없던 구간), 작성 중(토큰 수·속도),
   중단 처리 중, 완료·실패를 모두 문장으로 알립니다. 버튼도 `AI가 작성 중…`으로 바뀝니다.

`ContextWorker`는 단계(`stage`), 자료 묶음 진행(`chunk_index`/`chunk_total`), 작성한 글자 수를
평범한 속성으로 남기고 화면이 주기적으로 읽습니다. 진행률을 세려면 전체 묶음 수를 미리
알아야 하므로 자료 묶음을 한 번에 만들어 둡니다. 모델 준비 여부는 `MainWindow.model_ready()`
하나로 판단하며, 파일 크기까지 확인하므로 내려받다 끊긴 모델을 준비된 것으로 보지 않습니다.

진행 막대는 실제 진행률이 있을 때만 씁니다. 끝을 알 수 없는 작업에는 무한 반복 막대
(`setRange(0, 0)`)를 쓰지 않고 경과 시간이 1초마다 바뀌는 문구로 알립니다. 무한 반복 막대는
스스로 계속 다시 그려서 `QApplication.processEvents()`를 쓰는 화면 검증 스크립트를
끝나지 않게 만들기 때문입니다.

## 함께 고친 결함

창을 닫은 뒤에도 사례관리 화면의 주기 갱신 타이머가 살아 있어, 저장 위치가 사라진 뒤
데이터베이스를 읽다가 예외가 슬롯 밖으로 새어 나가면 프로그램이 그대로 죽었습니다.
`closeEvent`에서 `AI 작업 상태` 타이머와 사례관리 타이머를 멈추고, 맥락 읽기 실패는
화면에 사유를 적도록 했습니다. USB나 네트워크 폴더에 저장하는 경우에도 같은 문제가
생길 수 있어 함께 처리했습니다.

## 달라진 업무 흐름

1. **대상자 관리 → 확인할 일정**에서 기한이 지났거나 7일 이내인 모니터링 일정을 확인합니다. 일정을 더블 클릭하면 해당 대상자의 모니터링 탭으로 이동합니다.
2. **대상자 관리 → 대상자 목록**에서 이름·가명·연락처·주소로 검색합니다. 검색 결과 수와 필터 초기화를 제공하고, 대상자를 선택했을 때 관련 작업 버튼을 활성화합니다.
3. **서류작성 및 보관함 → 상담일지 작성**에서 대상자·실제 상담일·상담방법을 확인하고 메모를 입력합니다. 기본 양식은 상담일지입니다. 상세도·가명 변환용 성명·마스킹은 작성 옵션에서 변경합니다.
4. AI 초안을 검토하거나 오른쪽 본문에 직접 작성합니다. **상담 이력에 저장**을 누르면 정식 기록이 됩니다. 다시 수정하고 저장하면 같은 기록을 갱신합니다. 다음 상담은 **새 상담 시작**을 누릅니다.
5. **이력 조회·출력**에서 대상자·양식·기간별로 조회하고 인쇄 또는 PDF로 내보냅니다.

메모와 초안은 입력을 멈춘 뒤 약 0.7초 후 로컬 DB에 임시 저장됩니다. 사용자·대상자별 작성 내용이 분리되며, 앱을 다시 실행하고 같은 사용자·대상자를 선택하면 이어서 작성할 수 있습니다. 임시 저장은 상담 실적이나 서류 보관함에 추가되지 않습니다. 일반 상담은 대상자 미지정 슬롯에 보관합니다. 전체 DB 백업에는 임시 저장 내용도 포함됩니다.

단축키: 상담일지 작성 탭이 열려 있을 때 `Ctrl+Enter`는 AI 정리, `Ctrl+S`는 상담 이력 저장이며, `Esc`는 생성 중단입니다. `Ctrl+F`는 대상자 목록의 검색창으로 이동하고, `F11`은 전체화면을 전환합니다.

| template_manager.py / form_designer.py | 양식 수정 중 화면 재진입으로 변경 내용이 사라지는 문제 방지, 다른 양식 선택·사용자 전환·종료 시 저장 선택 |
| case_management.py / case_forms.py / case_form_templates.py | 단계별 서류 탭을 기본 화면으로 지정, 기존 14종 양식·진행단계·대상자별 입력 분리 검증 |
| form_document.py / prompts.py / anonymizer.py | 표 양식 변환·사실 중심 프롬프트·마스킹 흐름 점검, 본문의 역슬래시를 정규식 치환 문자로 오인하는 문제 수정, 마스킹 결과를 무조건 안전하다고 표시하던 문구 수정 |
| client_context.py | 원본 기록에 근거한 대상자 맥락, 변경·삭제 후 갱신 및 동시 변경 시 오래된 요약의 반영 방지 회귀 검증 |
| config.py / setup_dialog.py / download_model.py / 실행·배포 스크립트 | 저장 위치 전환과 백업·복원 호출 경로, 모델 경로와 소스 실행 방식 확인 |

상담 생성 중 변경할 수 없는 항목은 비활성화하고, 중단한 초안은 작성된 부분만 남깁니다. 예시 메모 불러오기·새 상담 시작·AI 재작성·원래 AI 초안으로 표 재적용 등 기존 내용을 바꾸는 작업은 확인 후 처리합니다.

## 검증 방법

2026-09-08 실행 결과: 전체 테스트 **60개 통과**(업무 메뉴 이동 경로와 AI 작업 진행 표시 검증 14건 추가, tests/test_navigation.py·test_client_context.py), 수정한 Python 파일의 컴파일 검사 및 `git diff --check` 통과. 업무 메뉴 4화면과 화면 안의 탭 9곳을 1366×768에서 가로 넘침 없이 확인했고, 880×540의 상담 작성 화면에서 세로 배치와 스크롤을 확인했습니다. `verify_ux.py`는 탭 안쪽 스크롤까지 함께 측정합니다. 설치된 로컬 Gemma 모델로 가상 메모를 실제 생성하여 `AI_SMOKE_OK`를 확인했습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe verify_ux.py
# 설치된 모델로 가상 메모 생성도 확인할 때
.\.venv\Scripts\python.exe verify_ux.py --ai-smoke
```

테스트와 화면 캡처는 임시 폴더의 가상 데이터로 실행합니다. 기존 업무 데이터와 config.json을 변경하지 않습니다. 화면 예시는 [상담 작성](ux_preview/counseling.png), [대상자 관리](ux_preview/clients.png), [서류 보관함](ux_preview/documents.png), [데이터 백업·복원](ux_preview/settings.png), [AI 작업 진행 표시](ux_preview/ai_activity.png), [작은 창](ux_preview/counseling_small.png)에서 확인할 수 있습니다.

검증 범위는 Windows의 PyQt6 화면·저장·백업 회귀 테스트와 가상 메모 생성입니다. Linux 실기기, 실제 프린터, 배포 EXE·설치본 재빌드는 이번 검증에 포함하지 않았습니다. 장문의 상담 메모가 모델 입력 한도를 넘는 경우의 자동 분할은 별도 개선이 필요합니다. 사례관리 보조 탭의 미저장 입력은 기존처럼 실행 중에만 대상자별로 유지되므로 해당 탭의 저장 버튼을 사용해야 합니다. 데이터 관리 · 데이터 백업·복원 탭 아래쪽의 `프로그램 설치 파일`과 `로컬 AI 정보`는 백업 업무와 직접 관련이 없으므로 별도 정리가 필요할 수 있습니다.

## 실행

이 폴더의 `사회복지_상담기록_AI_실행.vbs`를 다시 실행하면 수정한 Python 소스를 사용합니다. 이미 켜진 프로그램은 작성 내용을 저장하고 종료한 뒤 다시 실행합니다. `dist` 또는 기존 설치본의 EXE는 별도 재빌드가 필요합니다.
